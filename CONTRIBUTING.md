# Contributing to LazTrack 🤝

First of all, thank you for considering contributing to **LazTrack**! It's people like you that make open-source development so impactful.

By following these guidelines, you help us ensure a high-quality codebase and a smooth workflow for everyone.

---

## 🌿 Branching Strategy

To keep the development history clean and organized, we follow the **Fork and Pull Request** workflow:

1.  **Fork the repository** on GitHub.
2.  **Create a new branch** for your feature or bug fix:
    ```bash
    git checkout -b feature/your-feature-name
    # OR
    git checkout -b fix/your-bug-fix
    ```
3.  **Submit a Pull Request (PR)** against the `dev` branch.

---

## 💻 Code Style

We use modern React and TypeScript patterns:

-   **Language**: TypeScript (Strict Mode).
-   **Framework**: Next.js (App Router).
-   **Styling**: Tailwind CSS & Shadcn UI.
-   **State Management**: TanStack Query for asynchronous state.
-   **Components**: Keep components reusable and well-organized in the `components/` directory.

---

## 🚀 Pull Request (PR) Rules

When submitting a PR, please ensure you:

-   **Describe what changed**: List the specific changes you've made.
-   **Why it changed**: Explain the reasoning behind your decisions.
-   **How to test it**: Provide a brief guide or screenshots to verify your changes.
-   **Keep it focused**: One PR should ideally address one feature or bug fix.

---

## 🏷 Issue Labels

We use labels to help contributors find tasks that match their skills:

-   `good first issue`: Perfect for beginners getting started with the repo.
-   `bug`: Something isn't working as expected.
-   `enhancement`: New feature requests or improvements.
-   `help wanted`: We need extra eyes or expertise on a specific problem.

---

## 👋 Welcoming Environment

We are dedicated to building a welcoming and inclusive community. Whether you're a seasoned developer or just starting, your contributions are valued. If you have questions, feel free to open an issue or reach out!
